Privacy notice

This notice describes the administrator-only Google Drive integration for DailyLove Backups. It does not replace the DailyLove App’s end-user privacy policy.

Information accessed and its purpose

The integration reads the connected administrator’s email address to verify the expected account, reads Drive quota and backup-file metadata, and uploads, downloads and removes encrypted backup files within its configured folder. Downloads verify integrity and support administrator-run recovery. The requested Drive scope can access account files; operation is limited by the tool’s configuration to the dedicated backup folder.

Data and storage

Backup contents are encrypted with rclone crypt before upload to Google Drive. They include DailyLove business records and account recovery data, as well as database structure, access policies and image paths. Photo file contents are not backed up. Plaintext exports are handled only in the private backup runtime and isolated local recovery environment.

OAuth credentials and encryption configuration are stored as administrator-controlled local secrets and GitHub Actions Secrets. They are not included in the public repository or backup artifacts. Recovery keys are held separately by the administrator.

Use and sharing

Google user data is used only to operate, verify and recover the administrator’s backups. It is not sold, used for advertising, or used to train general-purpose AI models. Google Drive stores the encrypted files; GitHub Actions runs the configured backup jobs. No public file sharing is enabled by this integration.

DailyLove Backups’ use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements.

Retention and control

The normal retention policy keeps the latest seven daily backup dates, four weekly backups, and release backups for thirty days. Expired valid backups are removed only after a new backup has been verified. Failures may extend retention. The administrator may retain additional incident-recovery copies as needed.

The administrator can disconnect access through their Google Account’s third-party connections settings. Disconnecting stops future access but does not delete existing encrypted backups. Existing backup files and locally held copies must be managed separately by the administrator.
